# Finale Q&A sheet

Short, honest answers. Numbers come from `state.md`; do not round them up.

**Is any of this real data?**
The forecaster is trained and scored on India's real HMIS health data: WAPE 0.871 vs 1.078 for the
naive baseline on a held-out window, 19% better. The Nashik facility list is real. The weekly stock
ledger the demo runs on is synthetic, generated by a sealed generator, because facility-level stock
data is not public. The 6% stock-out reduction comes from a replay on that synthetic ledger.

**How accurate is the photo reading?**
On 206 rendered register lines in four scripts, Gemini read the quantity right 100% of the time and
the medicine 98.1%. Those are rendered text, not real handwriting photos; real-photo accuracy is
the first thing a pilot measures. Every photo read is confirmed by the nurse before it is saved.

**What if the forecast is wrong?**
Nothing moves without an officer approving it, and every forecast shows a range (p10-p90) and a
probability, not a single number. The served forecast is lag-1 naive because it beat LightGBM on
the most recent weeks; we pick the model by measurement, not by preference.

**Is it really on Google Cloud?**
Yes: Cloud Run in Mumbai, with Firestore for live stock, BigQuery for history, Pub/Sub carrying
WhatsApp messages to the backend, Cloud KMS signing every transfer order, Secret Manager for the
Gemini key and Vertex AI embeddings for medicine names, all provisioned with Terraform. For the demo,
sign-in is a demo picker and WhatsApp is the in-app simulator; Firebase Auth and Twilio are wired
in the code and are the next configuration step for a pilot.

**Where is Google AI used?**
Gemini reads register photos (live), Vertex AI embeds medicine names in 7 scripts (live), OR-Tools
solves the transfers (live). Chirp for voice notes and Cloud Translate / Text-to-Speech for alerts
are wired in cloud mode; the agent is rule-based over the same tools, so it can never be talked
into an action.

**Can the AI approve or send anything?**
No. The agent's tool list has no approve or send tool; we test this by name inspection and with a
prompt-injection attempt. Only a signed-in officer, within their jurisdiction, can approve.

**Privacy?**
Phone numbers are stored hashed. The public view shows district totals only, never a facility
identifier, and a test enforces that. Federated training lets states improve one model without
pooling raw data (it ties local-only accuracy, with privacy as the gain).

**Does rebalancing actually help, if total supply is short?**
It spreads scarcity: in the replay, stock-out weeks fall 6% while unmet units stay flat (+0.25%).
It does not create supply. The same forecasts can drive procurement, which is the next step.

**Cost to scale?**
Not measured yet. The serving footprint fits a 512 MB instance for one district (760 facilities).
Per-state GCP projects keep data within the state.

**What would a pilot need?**
One block in Nashik, its nurses' WhatsApp numbers, a few weeks of real register photos to measure
extraction, and an officer to approve transfers. The software is ready for that.

**Why WhatsApp?**
Nurses already use it; a new app is another login and another training. Low-confidence reads get a
one-tap confirmation card instead of a form.
